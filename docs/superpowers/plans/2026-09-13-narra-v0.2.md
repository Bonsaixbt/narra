# narra v0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Make narra see the whole life of a meta — pools after graduation, deep history, the wallets that carry capital between metas — and add an optional semantic layer on top of the deterministic clustering.

**Architecture:** Same single process. New ingest streams (PoolManager swaps + token transfers, deep backfill), new tables (`pool_swaps` filled, `wallet_stats`, `wallet_meta`), a pluggable `semantic/` provider for embeddings and cluster naming, and heat/flow/verdict extended with pool volume and wallet cohorts. Everything stays reproducible from SQL; the AI layer only adds links and labels, never overrides numbers.

**Tech Stack:** as v0.1 + optional `@huggingface/transformers` (local ONNX embeddings, lazy install) and OpenAI-compatible / Ollama / Anthropic HTTP for the semantic provider.

**Spec:** `docs/OSS.md`, `docs/STATUS.md`, this file.

## Global Constraints

- Deterministic core stays: any verdict must be explainable without the AI layer (`--no-semantic` must produce the same numbers minus semantic links).
- No private key, no trading, loopback-only HTTP. Unchanged.
- Any model call is opt-in, cached in SQLite, budget-capped, and off by default in the OSS build.
- Wallet tracking is cohort-level flow, not a copytrade signal: no "follow this wallet" verdicts.

### Task 2: History — deep backfill and compaction
**Files:** `src/ingest/sync.ts` (`--hours N`, parallel chunks when the first endpoint is private), `src/store/db.ts` (`hourly` table + compaction), `src/cli/backfill.ts`
**Produces:** `narra backfill --hours 168` on a private archive RPC; raw trades kept `NARRA_RETENTION_H` (default 48 h, set 168+ with own node); beyond retention, per-token-per-hour aggregates (`buys, sells, quote_in, quote_out, unique_buyers, taxed`) and per-cluster snapshots stay forever. Flow and heat read raw rows inside retention and hourly rows beyond it (delta over days, "how long has this meta been alive").
- [ ] Parallel chunk fetch: `Promise.all` over `concurrency` chunks when `endpoints[0].concurrency ≥ 4`.
- [ ] `hourly` compaction job in `prune()`.
- [ ] `narra now --window 24h|7d` reading hourly rows.

### Task 3: Traders — wallet cohorts
**Files:** `src/analyze/wallets.ts`, `src/store/db.ts` (`wallet_stats`, `wallet_meta`), `src/cli/wallets.ts`, `src/schemas.ts`
**Produces:** per wallet, recomputed each tick from `curve_trades` + `pool_swaps`: tokens bought, buys/sells, quote in/out (realised PnL in ETH on curves and pools, no price oracle needed), median entry time after launch, share of buys that paid the opening tax (bot score), distinct metas touched, current meta. Cohort labels: `sniper` (tax buys > 50 %), `sprayer` (> cap tokens/window), `rotator` (≥ 3 metas in 4h with net positive PnL), `early-in-hot` (bought HOT-cluster members within 5 min of launch, ≥ 3 times). Flow edges gain `cohort_mix`; heat gains `rotator_share`; verdict gains a reason "N rotators entered in the last 10 min".
- [ ] `narra wallets [--cohort rotator] [--window 4h]` table and JSON; `narra wallet <address>` card (public data only).
- [ ] Not a copytrade: no `FIRE`, no wallet-follow mode. Documented in SAFETY.

### Task 4: Semantic layer (optional, pluggable)
**Files:** `src/semantic/provider.ts` (interface), `src/semantic/local.ts` (transformers.js, `Xenova/multilingual-e5-small`), `src/semantic/openai.ts` (any OpenAI-compatible `/v1/embeddings` + `/v1/chat/completions`: OpenAI, Ollama, LM Studio, OpenRouter), `src/semantic/anthropic.ts` (cluster naming/categorising only, no embeddings), `src/store/db.ts` (`embeddings(token, model, vec BLOB)`, `semantic_tags(token, model, tags_json)`), `src/analyze/cluster.ts` (4th link kind `semantic`)
**Design:**
1. **Embeddings per token** (name + symbol + first sentence of description). Cosine ≥ `semantic.threshold` (start 0.82) becomes a `semantic` link, same rules as name links (needs support, never alone merges two large groups). Multilingual model so 金狗 and "golden dog" land together. Local model: ~120 MB download once, CPU, ~2 ms/token after warm-up; 24k launches/day is fine.
2. **Category tags** from a fixed taxonomy (`animal, stock, ai-agent, politics, chinese-culture, crypto-meta, tool, celebrity, holiday, nsfw, other`): either zero-shot by embedding similarity to taxonomy anchors (free, local) or by a small LLM call per token (paid; cached; batched 50 per call). Tags enter `tokenize()` with weight 0.8 so a cluster can be named `animal-dog` even when no literal word repeats.
3. **Cluster naming and one-line summary** by LLM, only for published clusters (≤ 30 per tick, cached by member-set hash): "stock memes riding HOOD listing news". Shown as `label`, never used for linking.
4. **Config:** `NARRA_SEMANTIC=off|local|openai|anthropic`, `NARRA_SEMANTIC_URL`, `NARRA_SEMANTIC_KEY`, `NARRA_SEMANTIC_MODEL`, `NARRA_SEMANTIC_BUDGET_PER_DAY` (calls). `narra doctor` reports the provider and cache hit rate. `narra why` shows `semantic links` count and the tag source.
5. Provider interface: `embed(texts: string[]): Promise<Float32Array[]>`, `label(items): Promise<Tag[][]>`, `name(cluster): Promise<{label, summary}>`; each optional.
- [ ] Interface + local provider + cache + link kind + tests with a fake provider.
- [ ] OpenAI-compatible provider (covers Ollama) + Anthropic naming provider (read current API docs before wiring).
- [ ] Evaluate on a day of data: how many links are semantic-only, whether `mixed`/wallet-only clusters get names.
